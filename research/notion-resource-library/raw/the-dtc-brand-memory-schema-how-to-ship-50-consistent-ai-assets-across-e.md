## ⚙️ The Hidden Mechanism — Brand Memory > Image Generation
Most DTC operators think AI creative is an image generation problem. It's not.
It's a brand memory problem.
You can generate 1 clean product shot with GPT Image 2.0 in 30 seconds. The shot looks great. The lighting matches your brand. The product is exactly right.
Then you need:
→ 5 ad variations for Meta<br>→ 3 landing page hero images<br>→ 2 email banners<br>→ 4 product page lifestyle shots<br>→ 6 social posts for Instagram<br>→ 4 retargeting display ads
24 assets. All meant to be the same brand. By asset 24, what you'll have:
→ Packaging that shifted color between asset 8 and asset 15<br>→ Typography that drifted from sans-serif to serif on asset 12<br>→ Lighting that broke between platforms — soft window light on ads, harsh studio on landing pages<br>→ The customer in the lifestyle shot changed face 3 times across the 24 assets<br>→ Every output feels like a different freelancer made it
The reason: each generation starts from a blank prompt. Even if you describe the brand the same way every time, GPT Image 2.0 interprets the description differently across generations. Without persistent memory, you're rolling dice 24 times in a row.
The fix is structural: load the brand context ONCE into a persistent memory layer, then have every generation pull from that memory instead of starting from blank.
That's what the Brand Memory Schema is. 6 schema fields that capture every variable that should NOT drift across assets. Loaded into Higgsfield Supercomputer's Working Memory Hub. Pulled automatically by every GPT Image 2.0 generation downstream.
The fix is not better prompts. The fix is **persistent brand memory** — the thing that lets 50 assets share the same visual DNA without manual correction.

The schema is now persistent in the Working Memory Hub. Every future GPT Image 2.0 generation inside Higgsfield pulls from it automatically — but only if you explicitly reference it in the prompt.
The reference prompt:
```javascript
Generate this asset using the [BRAND] Brand
Memory v1 from the Working Memory Hub.

Pull from:
- buyer_profile (lock the customer archetype)
- product_positioning (lock the hero claim)
- visual_aesthetic (lock palette + lighting +
  mood)
- packaging_rules (lock product appearance)
- typography_rules (lock font + weight +
  hierarchy)
- hook_angle_library (use angle: [SPECIFIC
  ANGLE FROM LIBRARY])

Asset spec:
[CHANNEL-SPECIFIC PROMPT — see 6 prompts in
Section 8]

Constraints:
- Maintain exact buyer_profile across this asset
  and all sister assets
- Maintain exact packaging_rules — no label
  drift, no proportion drift
- Maintain visual_aesthetic — palette, lighting,
  mood locked
- Output: [DIMENSIONS — 1080x1920 for vertical
  social, 1200x628 for ad, 1920x1080 for
  landing hero, etc.]
```
Every asset generation starts with this reference. The schema does the heavy lifting downstream.

## ⚙️ What NOT to Do
→ Don't generate assets without referencing the memory in the prompt. Without the explicit reference, GPT Image 2.0 falls back to blank-prompt defaults.
→ Don't update the schema mid-batch. If you change packaging_rules between asset 10 and asset 11, you've created drift you'll regret. Update between batches only.
→ Don't load junk into the schema. Each field must capture the ACTUAL brand standard, not aspirations. Drift starts when the schema is theoretical.
→ Don't skip the brand audit (Step 1). Without knowing which drift symptoms you have, you'll lock the wrong fields.
→ Don't use generic descriptors in the schema. "Casual" is not a buyer_profile.archetype. "Woman 28-40 with natural glow, dark hair, white linen shirt, no heavy makeup" is.
→ Don't expect 100% consistency on the first batch. The first batch reveals the schema gaps. Refine after batch 1, then run batch 2 cleaner.
→ Don't skip the 9-point review. The schema reduces drift by 80-90%, not 100%. The 9-point review catches the last 10%.
→ Don't override the schema for a "creative experiment" without versioning. Save it as v1.1-experimental so you can roll back.
→ Don't use the same schema for multiple brands. Each brand needs its own Brand Memory v1. Cross-contamination kills consistency.
→ Don't expect the schema to fix bad inputs. If your brand kit PDF is inconsistent to start with, the schema will lock inconsistency.
→ Don't run the schema in isolation from your creative tools. Every tool in your stack should reference the same memory. If only 1 tool references it, the others will produce drift.

<td>Customer face changes across 20 assets</td>
<td>Identity strength too low. Add "Lock buyer_profile identity strength to 0.9+" in every channel prompt.</td>
</tr>
<tr>
<td>Typography drifts in email vs ad</td>
<td>typography_rules.color_on_image not specified for low-contrast scenarios. Add fallback rules.</td>
</tr>
<tr>
<td>Schema updates break consistency mid-month</td>
