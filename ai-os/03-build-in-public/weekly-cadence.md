# Weekly Cadence

The existing rhythm, with the build layered on. Nothing new to invent — the publishing schedule already works and the build fits inside it.

---

## The week

| Day | Channel commitment | Build commitment | Who runs it |
|---|---|---|---|
| **Mon** | CTR audit, weekly plan, LinkedIn post | Weekly review (5 questions) | Operator + Paras |
| **Tue** | **9am publish** + 48h protocol, first-2h comments | — | Operator |
| **Wed** | Shorts (evening) | **Live build session** — this week's agent | Paras |
| **Thu** | WhatsApp broadcast | **Film next batch** | Paras + Editor |
| **Fri** | **9am publish** + 48h protocol, Community Tab | — | Operator |
| **Sat** | X thread | Deep work — harden the week's agent, research | Paras |
| **Sun** | Shorts (evening), IG carousel | Plan next week | Operator |

**Two load-bearing days:**

- **Thursday.** Filming feeds everything downstream. A missed Thursday surfaces as a missed publish nine days later — far enough out that the cause gets misdiagnosed as an editing problem.
- **Wednesday.** The live build is where the agent actually gets made. Skip it and the week's content has no subject.

---

## The build fits in three slots

| Slot | Hours | What happens |
|---|---|---|
| Wed live session | 1.5 | The agent gets built, in public |
| Sat deep work | 3–4 | Hardened, spec written, edge cases |
| Mon review | 0.5 | Did it hold up, what's next |

**Roughly six hours a week of build time.** That is the honest budget at this headcount, and it is enough for one agent a week when six of the nine already exist and the work is wiring.

Anything requiring more than six hours a week is too big for this phase and should be split.

---

## The 48-hour protocol

Runs after every Tuesday and Friday publish. Already specified in `paras-publishing-package`; owned by the Operator.

| T+ | Action |
|---|---|
| 0 | Publish 9am IST. Pinned comment live. |
| 0–2h | **Reply to every comment.** Highest-value window there is. |
| +2h | Community Tab post |
| +3h | IG story teaser |
| +4h | Skool post — with the agent attached |
| +6h | Check CTR/AVD; flag if off-target |
| +24h | GHL email to list |
| +24h | IG carousel |
| +48h | LinkedIn long-form; WhatsApp broadcast |

The first two hours are the part that cannot be delegated to a schedule. Early comment velocity is a ranking input and a community signal at once.

## Quarterly (week 13)

90-day review, published as content. Every agent spec updated, roster status column refreshed, next 90 days planned from actual data rather than from the previous plan.

---

## What protects the cadence

Three rules, and they exist because the cadence is the first thing that breaks:

1. **Publishing is never traded for build progress.** A week with a shipped agent and a missed publish is a failed week. The channel is the bottleneck; the build is downstream of it.
2. **Maintain a three-week script buffer.** When it drops below two, Thursday's filming overrides everything else on the board, including the build.
3. **One agent a week, maximum.** Two half-built agents are worth less than one finished one, and the six-hour budget does not stretch.

---

## When to break rhythm

- **Pipeline under two videos ready** → drop the build, film.
- **Last publish CTR badly off** → Monday becomes a full repackage instead of an audit.
- **A real failure worth showing** → it displaces the planned episode. Failure content outperforms and builds more trust than a clean week.
- **Seven-plus consecutive days without rest** → take one. Burnout at week six costs more than any single week's output, and the whole plan assumes a person who is still doing this in month twelve.
